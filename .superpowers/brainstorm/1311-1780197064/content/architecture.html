架构设计方案

基于已确认的技术栈（Next.js + React + TS + Tailwind + SQLite），以下是 2 种实现路径

方案 A：参考项目深度复用 + 后端增强

前端（参考项目组件大量复用）
page.tsx 主页面 + PixelatedPreviewCanvas + ColorPanel + ToolBar + SettingsPanel
↑ fetch / TRPC
Next.js API Routes（新增）
/api/projects (CRUD) · /api/export (PNG/PDF) · /api/palette (色卡数据)
↑ sqlite3 / better-sqlite3
SQLite 数据库（新增）
projects 表 · patterns 表 · cells 表

优点

  • 像素化、色卡匹配、画布编辑等核心逻辑直接复用
  • 开发速度最快，风险最低
  • 参考项目经过验证，bug 少

缺点

  • 前端页面可能较大（参考项目 page.tsx 138KB）
  • 需要理解并适配参考项目的数据结构
  • 后续扩展可能需要重构

方案 B：借鉴思路 + 重新构建

前端（全新构建，模块化）
UploadPage · EditorPage · ExportPage，每页独立，共享 hooks 和 utils
↑ REST API
Next.js API Routes
独立 route handlers，清晰的请求/响应契约
↑ sqlite3
SQLite 数据库
按 PRD 数据模型设计：Project / Pattern / Cell / PaletteColor

优点

  • 代码结构清晰，可维护性好
  • 数据模型按 PRD 设计，扩展性强
  • 不受参考项目架构约束

缺点

  • 开发量更大，需要重新实现像素化和编辑逻辑
  • 需要更多测试来确保稳定性
  • 时间成本更高

我的推荐：方案 A。参考项目的核心算法（像素化、色卡匹配、局部编辑）实现得很扎实，复用可以节省大量时间。将单体 page.tsx 适当拆分为组件，再叠加后端持久化，是性价比最高的路径。
